## 評価の定義

正本は [research-premises.md](../../research-premises.md) の「公平性のスコープ：動作点」。

- **主**：固定しきい値 0.5 での群別 TPR・FPR の差（Eopp1・Eopp0・Eodds）と、害の大きい側の最悪群の率。
  - CheXpert（No Finding が陽性）：最大の FPR（見落とし）
  - HAM10000・FairVLMed：最小の TPR（見落とし）
- **副**：全体 AUROC、最悪群 AUROC、AUROC gap（しきい値によらない指標）

**改善と呼ぶ条件**：次の 3 つを同時に満たすこと。

- 全体の性能を落とさない（できれば上げる）
- 群のあいだの差を縮める
- そのために最悪群の性能を上げる

最悪群が上がっていなければ、改善とは呼ばない。したがって次の 2 つは、差が縮んでいても改善に数えない。

- 両方の群が下がって差が縮んだ場合（leveling down）
- しきい値（動作点）がずれただけで、最悪群の性能が上がっていない場合

## 柱 A：hypernetwork による条件付けは、いつ効いて、いつ効かないか

### 問い

属性を入力に hypernetwork で重みを変える条件付けについて、次を明らかにする。

- 性能と公平性に効果が出るのは、どんなデータ・目的関数・学習手順のときか
- 効果が出ないとき、その原因は何か

| 軸 | 水準 |
|---|---|
| データ | CheXpert / HAM10000 / FairVLMed |
| モデル | ResNet（条件付けなし）/ Spatial LoRA / HyperAdapt |
| 目的関数 | ERM / 公平性損失（GroupDRO、FairDRO、minimax AUC、EO rate など） |
| 学習手順 | e2e（1 stage）/ 2 stage |

### 現状

実験は回したが、結論を出せる状態ではない。理由は次の 3 つ。

**1. 公平性損失の実装に誤りがあった。** 2026-10-13 に修正した（`7877f1c`・`6a09df9`）。詳細は
[20261013_fairness_objective_fixes.md](../../reviews/20261013_fairness_objective_fixes.md)。

- EO rate：代理制約が予測を閾値の反対側へ動かせず、群間差を縮める勾配がなかった。
- GroupDRO：自然抽出のとき、バッチに出なかった群の重みが系統的に縮んでいた。少数群ほど強く縮む。
- FIS：c が混合比として働いていなかった。
- DANN：adversary の head が属性を読めていなかった。

**2. 比較が対照実験になっていない。** 成功した e2e の run を、データ × 目的関数 × モデルで数えると次のとおり。

| データ | 目的関数 | ResNet | Spatial LoRA | HyperAdapt |
|---|---|---|---|---|
| CheXpert | ERM | 7 | 7 | 3 |
| | GroupDRO（年齢×人種）※ | 8 | 26 | 12 |
| | minimax AUC / FairDRO（年齢） | 各 1 | 各 1 | — |
| | EO（年齢）※ | 1 | 1 | — |
| | DANN ※ | 14 | — | — |
| HAM10000 | ERM | 30 | 97 | 4 |
| | GroupDRO ※ | 12 | 6（GMM8 のみ） | — |
| | EO ※ | 9 | 3 | — |
| | minimax AUC | 9 | 3 | — |
| | FairDRO、PopAUC、UniformGroup、FIS ※、FaMI | 各 6 | — | — |
| | ℓ_wst | 21 | 12 | — |
| FairVLMed | ERM のみ | 4 | 19 | 4 |

※ 10/13 に修正した不具合の影響を受ける run。

- HAM10000 の公平性損失は、ほとんど ResNet だけで回している。HyperAdapt は 0 本。
- CheXpert で 3 つのモデルを比べられる公平性損失は GroupDRO だけで、これは不具合の影響を受けている。
- FairVLMed には目的関数の軸がない。
- seed 数が条件ごとに 1〜3 本でばらばら。
- 学習手順（e2e・親 ERM からの継続・2 stage）は、config から機械的に見分けられなかった。
  ImageNet の重みと親 ERM の重みが、同じ設定項目（`backbone_checkpoint_path`）に入っているため。表では区別していない。

**3. 網羅的に回せていない。** run の本数は多いが、同じ条件どうしを比べられるマスがほとんどない。

### 必要なこと

- データ × 目的関数 × モデル × 学習手順のうち、問いに答えるのに必要な格子を決める。
  そのうえで、seed をそろえて対照実験として回す。
- 修正前の EO・GroupDRO・FIS・DANN の結果は使わない（上の「過去の実験結果の扱い」）。

## 柱 B：hypernetwork で潜在サブグループを扱うのは妥当か、効果はあるか

### 問い

- **捕捉**：条件付きの予測で、どんなバイアスを捕まえられて、どんなバイアスを捕まえられないか
- **工夫**：捕まえるためにどんな工夫ができるか
- **改善**：有用な潜在サブグループが見つかったとき、それを使って改善できるか（基準は上の「改善と呼ぶ条件」）

### 動機

既知の属性の組み合わせで交差群を全部作ると、群が多くなりすぎる。そこで、特徴空間に現れる自然なバイアスから群を見つけたい。
交差群を細かくするとセルの下限（20 件）を割るので、データから意味のある束ね方を見つけたいという問題設定は妥当である。

### これまでの実験

初期の案として、Spatial LoRA を 1 stage・ERM で学習し、次の 2 つの空間でクラスタリングした。

- metadata encoder の出力空間（入力は属性メタデータ）
- 生成パラメータの空間

妥当かどうかは確かめていない。「とりあえずクラスタリングしてみた」段階にある。

### 初期案で捕まえられるもの・捕まえられないもの

コードで確かめた事実は 1 つだけである。Spatial LoRA の条件は `metadata_encoder(attributes)` だけから作られ、画像は入らない。
生成パラメータもこの条件だけで決まる（`projects/hypernet_e2e/models/spatial_hypernet/network.py:99`）。
以下は、この事実からの推論で、実験では確かめていない。

**1. 見つかる群は、属性の組み合わせを束ね直したものに限られる。**

- 2 つの空間はどちらも属性だけの関数なので、同じ属性の人は必ず同じ点に写る。
- クラスタリングで得られるのは、属性の交差群を、モデルが似ていると見なした順に束ねたもの。年齢のような連続値は、学習で決まった区切りになる。
- 属性で書けないバイアスは原理的に見つからない。画像の写り方や、ラベルの付き方によるものがそれにあたる。
  - 例：CheXpert で高齢の No Finding に追跡撮影のレポートが多い件は、ap_pa と年齢がメタデータにあるので、間接的になら掛かりうる。
  - レポートの書き方そのものは掛からない。

**2. ERM で学習した空間の距離は、「性能が悪い」ではなく「予測の仕方が違う」を表す。**

- encoder は損失を下げる向きに学習するので、離れて写るのは、陽性率や見た目の傾向が違い、予測を変えたほうが得な属性の組み合わせである。
- 柱 B で欲しいのは、モデルが不利に扱っている群（最悪群の率が悪い群）であり、両者が一致する保証はない。
- 群ごとに陽性率が違うだけでも、クラスタははっきり分かれうる。

### 工夫の方向

| 方向 | 中身 | 補う点 |
|---|---|---|
| 誤差の信号を入れる | ERM の誤り（見落とし）を属性から予測するモデルを作り、その空間で束ねる。監査（multiaccuracy）系の考え方 | 2：距離が性能の悪さを表さない |
| 画像側の情報を入れる | ERM の特徴量や誤りの出方で束ねる（LHCF 系） | 1：属性で書けないバイアスを拾えない |
| 妥当性を検定する | 正解の分かっている群を植え込んで回収できるかを見る。見つかった群の性能差が偶然以上かを見る | 1・2 の両方を確かめる |

repo には近い試みの断片がある。`analysis/archive/direction_poc` の multiaccuracy、`analysis/conditioned_subgroup_discovery` の植え込み、
LHCF のコホートである。いずれも整理されていないので、使えるかは個別に確かめる。
