# hypernetwork にバイアスを溜めて発見する設計：cross-fit・凍結・二系統の振り分け（2026-10-08）

## 結論

**hypernetwork 側にモデルのバイアスを溜めるには、1段目を凍結し、1段目が学習していないデータで補正を学習する。
条件（振り分け）にはモデル自身の表現 h(x) とタスク非依存の画像表現 e(x) の両方を入れ、
読むのはグループ番号ではなく補正の向きと量にする。**

この方針は、正解の分かっている2種類の植え込みバイアスで確かめた。

- **モデル側のショートカット**（画像上のマーカーを陽性の手がかりとして覚えさせた）
  - 発見：補正量の大きい順に並べると、マーカー付き画像を AUROC 1.00 で当てた。
  - 修正：test AUROC 0.790 → 0.859。陰性での偽陽性率は、マーカー付き 0.76 とマーカーなし 0.14 の差が、0.22 と 0.23 にそろった。
- **データ側の隠れた部分集団**（ペースメーカーの陽性を学習データで1割に間引いた）
  - 発見：振り分けたコードが、ペースメーカー画像を AUC 0.72〜0.80 で分離した。
  - 修正：この群の陽性の TPR 0.45 → 0.72〜0.74（間引かない場合は 0.77）。

実データの CheXpert No Finding では、同じ手法でも大きな潜在バイアスは見つからなかった。
得られた補正は全体 AUROC で +0.003〜+0.008、worst-group には有意な変化がない。
回収できたのは「追跡撮影」「レポートが特定の問いにだけ答える」といった、属性に無い文脈である。
既存の機構診断（`fairness_mechanism_probe`）の結論と食い違わない。

設計上の判断は4つに整理できる。

| 判断 | 採る方針 | 根拠（本文の節） |
| --- | --- | --- |
| 補正を何で学習するか | 1段目が見ていないデータ（cross-fit、または展開先の監査データ） | 1節。in-sample では補正が1〜3 epoch で止まる |
| 1段目を凍結するか | 凍結する | 2節。同時学習では補正の大半が backbone 側へ移る |
| 何で振り分けるか | h(x) と e(x) を連結する | 3節。どちらか一方では片方の種類を見落とす |
| 何を読むか | 補正の向き（ΔW）と1枚ごとの補正量、seed をまたいで安定な要因 | 4節。コード番号は seed ごとに入れ替わる |

あなたの過去の実験（凍結した ResNet に adapter を付けて同じ train で再学習）が改善しなかった理由も、これで説明が付く。
in-sample で学習したことは不利に働いたが、M01 程度の過学習なら損は AUROC 0.001〜0.002 にとどまる。
主因は、CheXpert No Finding には属性で条件付けて直せる系統的な残差がもともと少ないことにある。

## 1. 補正は1段目が見ていないデータで学習する

train を患者単位で A / B に二分した split（`data/chexpert/splits_crossfit/`）を作った。
1段目の ResNet-50 を A だけで学習し、同じ補正を A（in-sample）と B（cross-fit）でそれぞれ学習して、
同じ test で評価した。補正は分類 head への ΔW（rank 4）と Δb である。
数値は3 seed の平均で、補正前との差を示す。

| 1段目 | 補正（rank 4） | 学習データ | 選ばれた epoch | 損失の変化 | AUROC の変化 |
| --- | --- | --- | ---: | ---: | ---: |
| A で学習 | 全員共通 | A（in-sample） | 1.3 | −0.008 | +0.001 |
| A で学習 | 全員共通 | B（cross-fit） | 26.0 | −0.017 | +0.003 |
| B で学習 | 全員共通 | B（in-sample） | 1.3 | −0.010 | +0.001 |
| B で学習 | 全員共通 | A（cross-fit） | 13.0 | −0.042 | +0.005 |
| A で学習 | 属性で条件付け | A / B | 7.7 / 27.0 | −0.007 / −0.018 | +0.001 / +0.004 |

in-sample の補正は、val 損失が1〜3 epoch で悪化に転じて止まる。
1段目がすでに合わせ込んだ残差には、汎化する成分がほとんど残っていないからである。
患者単位の paired bootstrap では、cross-fit の全体 AUROC +0.0033 は 95% 区間 [+0.0008, +0.0052] で 0 を含まない。
in-sample の +0.0012 は [−0.0005, +0.0029] で、0 を含む。

in-sample の損は、1段目の過学習の度合いで変わる。
1段目の train と held-out の AUROC の差は次のとおりで、B で学習したモデルが最も大きく、cross-fit との差も最も開いた。

| 1段目 | 自分の train | 見ていない train / val / test |
| --- | ---: | ---: |
| A で学習（best epoch 3） | 0.882 | 0.860 / 0.861 / 0.857 |
| B で学習（best epoch 10） | 0.898 | 0.864 / 0.862 / 0.852 |
| M01（race-known train 全体） | 0.886 | — / 0.868 / 0.858 |

backbone 側の Spatial LoRA（stage3・stage4・fc、hypernet_e2e の2段目と同じ構成）でも向きは同じだった。
val で選んだ epoch の test AUROC の変化は、cross-fit が +0.0025〜+0.0028（区間は 0 を含まない）、
in-sample が +0.0017〜+0.0018（区間は 0 を含む）。属性で条件付けても、条件付けなくても変わらなかった。

例外が1つある。切片だけの補正や、e(x) で振り分けて切片だけを足す補正は、in-sample でも cross-fit でも同じ程度に効いた。
in-sample で効かなくなるのは h(x) の向きを使う補正で、記憶が残っているのはその表現の中だからだと考える。

## 2. 同時学習では、補正は hypernet の外へ逃げる

植え込みモデルの上で、Spatial LoRA を B で学習した。backbone を凍結した場合と、backbone ごと更新した場合を比べる。
学習後に LoRA を外し、backbone と共有 classifier だけで test を評価した（`probes/eval_adapter_off.py`）。

| 植え込み | 学習 | 1段目 | LoRA あり | LoRA を外す |
| --- | --- | --- | --- | --- |
| マーカー | 凍結 | AUROC 0.790、偽陽性率 0.76 / 0.14 | 0.858、0.30 / 0.29 | 0.790、0.76 / 0.14 |
| マーカー | 同時 | 同上 | 0.852、0.28 / 0.28 | 0.850、0.29 / 0.29 |
| ペースメーカー | 凍結 | 陽性 AUROC 0.720、TPR 0.45 | 0.805、0.74 | 0.720、0.45 |
| ペースメーカー | 同時 | 同上 | 0.831、0.73 | 0.790、0.68 |

偽陽性率は「マーカー付き / なし」の陰性、陽性 AUROC は「ペースメーカーの陽性 vs 全陰性」で測った。

凍結なら、LoRA を外すと1段目にそのまま戻る。補正はすべて hypernet 側にある。
同時学習では、LoRA を外してもマーカーの偏りは消えたままで、ペースメーカーの修正も大半が残る。
修正そのものは同時学習でもできるし、全体 AUROC はむしろ高い（0.863）。
ただし「どこがバイアスか」は、もう hypernet の出力からは読めない。
発見を目的にするなら凍結、性能だけが目的なら同時学習、という使い分けになる。

## 3. 振り分けの入力は、モデル側と データ側の両方が要る

補正のグループ（K=16）を、どの入力から振り分けるかで比べた。
数値は、test でグループ番号から植え込み要因をどれだけ当てられるか（val で求めたグループ別の率をスコアにした AUROC）と、修正後の指標である。

| 振り分けの入力 | マーカー：回収 | マーカー：修正後 AUROC | ペースメーカー：回収 | ペースメーカー：陽性 TPR |
| --- | ---: | ---: | ---: | ---: |
| 補正なし | — | 0.790 | — | 0.45 |
| 全員共通（K=1、rank 4） | — | 0.859 | — | 0.60 |
| 属性（現行の hypernet と同じ入力） | 0.50 | 0.858 | 0.59 | 0.60 |
| h(x)：1段目の表現 | **0.999** | 0.858 | 0.65 | 0.64 |
| e(x)：RAD-DINO | 0.53〜0.64 | 0.833〜0.858 | 0.71〜0.73 | **0.68〜0.72** |
| h(x) と e(x) の連結 | **0.995〜0.998** | 0.858 | **0.72〜0.76** | 0.68〜0.71 |

2つの植え込みは、性質が逆である。

マーカーは、モデルが覚えたショートカットとして h(x) にはっきり符号化されている。
h(x) で分ければ完全に分離でき、RAD-DINO はこの小さな白い四角をほとんど拾わない。
またマーカーの偏りは群内の順位を壊していない（群内 AUROC はマーカー付き 0.863、なし 0.851）。
ずれは群ごとの切片だけなので、向きを1本持つ全員共通の ΔW でも直る。

ペースメーカーは、1段目が陽性の例をほとんど見ていない部分集団である。
モデルの表現はこの部分集団を目立たせない（h(x) で 0.65）。一方、RAD-DINO は胸部X線の中のデバイスを捉えている（0.71〜0.73）。
backbone 側の振り分け（凍結）では、上位のコードがペースメーカー画像を 38% と 33% 含んだ。全体の率は 8.6% である。分離の AUC は 0.80 だった。

属性で振り分ける現行の hypernet は、どちらの植え込みも回収できない。属性に無い要因は、属性からは原理的に分けられない。
DINOv2（自然画像の自己教師あり）でも文脈の回収はできたが、補正の効果は RAD-DINO の1/7程度（全体 AUROC +0.0010 と +0.0071）だった。

## 4. グループ番号は読めない。読むのは補正の向きと量

振り分け係のグループは、seed を変えると入れ替わる。test の割り当ての一致（ARI、3 seed の組の平均）は次のとおり。

| 振り分け | ARI |
| --- | ---: |
| e(x) の振り分け係（容量・λ・入力の次元を変えても） | 0.09〜0.18 |
| 属性の振り分け係 | 0.33〜0.45 |
| e(x) の k-means | 0.38 |
| h(x) の k-means | 0.56〜0.61 |

損失がほぼ同じになる分け方が多数あるため、どれに落ちるかが初期値で決まる。
容量を絞った線形の振り分け係でも安定しなかった。
一方、e(x) の k-means は安定しているが、誤りと無関係に分けるので補正の効果はほぼ無い（全体 AUROC +0.0004）。

seed をまたいで安定するのは、要因の水準での回収（どの seed でもペースメーカーを 0.70 前後で分離する、など）と、補正の向きのほうだった。
全員共通の rank 1 の ΔW だけを学習し、1枚ごとの補正量 ΔW·h(x) で test を並べると、マーカー付き画像を AUROC 1.00 で当てた（3 seed とも）。
**向き1本で表せるショートカットなら、グループを作らなくても ΔW の向きそのものが検出器になる。**
ペースメーカーのように1段目の表現で目立たない部分集団は、向きだけでは足りず（補正量による並べ替えで陽性内 0.63）、e(x) での振り分けが要る。

## 5. 実データの CheXpert では、見つかったのは文脈で、改善は小さい

植え込みの無い1段目（A で学習）で、B を使って補正した。test の結果は3 seed の score 平均を使い、患者単位の paired bootstrap で評価した。

| 補正 | 全体 AUROC の変化 | worst-of-8 の変化 |
| --- | --- | --- |
| 全員共通（rank 4） | +0.0033 [+0.0008, +0.0052] | +0.009 [−0.018, +0.047] |
| 属性の振り分け（rank 4） | 全員共通より +0.0012 [+0.0005, +0.0018] | 全員共通より +0.004 [−0.001, +0.009] |
| e(x) の振り分け（切片のみ） | +0.0096 [+0.0072, +0.0118] | +0.007 [−0.009, +0.030] |
| e(x) を線形に足した対照（PCA 256） | +0.0072（1本） | −0.006（1本） |

属性で条件付けると、高齢群の AUROC が全員共通より +0.0034 [+0.0016, +0.0051] 上がった。年齢との交互作用は小さいながら存在する。
e(x) の振り分けによる改善は、e(x) をそのまま線形に足した場合と同程度だった。
これは公平性の改善ではなく、RAD-DINO が持つ情報を足した効果と読むのが妥当である。
worst-group はどの補正でも区間が 0 をまたぐ。

それでも、e(x) で分けたグループには属性で説明できない要因が入っていた。
グループ番号から当てた AUROC と、そのうち既知の属性（8群×撮影方向×性別）を超えた分は次のとおり。

| 要因 | 属性だけ | e(x) のグループ | h(x) と e(x) のグループ |
| --- | ---: | ---: | ---: |
| 追跡撮影（同じ患者の2回目以降） | 0.54 | 0.62（+0.07） | 0.63〜0.65 |
| レポートが特定の問いにだけ答える | 0.65 | 0.68〜0.70（+0.05） | 0.70 |
| レポートがデバイスに触れる | 0.65 | 0.65〜0.67（+0.03） | 0.65 |

1枚ごとの補正量を属性と文脈ラベルで回帰すると、説明できたのは R² 0.04〜0.15 だった。
補正の大半は、名前の付く部分集団に揃っていない。
CheXpert No Finding には、属性やレポート文脈で切り出せる大きな潜在バイアスは無い、というのが今回の観測である。

## 次に何をするか

**1. 発見の手順を、次の形で固定する。**

1. 1段目を学習する（または既存モデルを使う）。
2. 1段目が見ていない監査データ（cross-fit した train の残り半分、または展開先のデータ）を用意する。
3. 1段目を凍結し、[h(x); e(x)] で振り分ける hypernet 補正（head、必要なら stage4 の LoRA）を監査データで学習する。
4. 読む対象は次の3つ。
   - 全員共通の ΔW の向きと、1枚ごとの補正量の上位例
   - 補正量と属性・文脈ラベルの関係
   - seed をまたいで再現する要因

   グループ番号そのものは報告しない。

**2. 実験の主戦場を CheXpert から移す。**
CheXpert No Finding では、発見すべき大きな潜在バイアスが見当たらなかった。
HAM10000（ruler・ink・暗い四隅などの既知アーチファクト）や FairVLMed で、同じ手順を回すのが次の一手になる。
どちらも属性に無いアーチファクトの存在が知られており、回収の答え合わせができる。

**3. 改善を主張するなら、植え込みと実データを分けて書く。**
植え込みでは大きく直る。実データの改善は全体 AUROC で 0.01 未満、worst-group は雑音の範囲である。
「発見の道具としての hypernet」を主にし、「公平性の改善手法」とは主張しないほうが、今の証拠に合う。

## 方法

- split：`data_pipeline/chexpert_crossfit_splits.py`。race-known の train を患者単位で半分ずつ A（79,493枚）と B（78,359枚）に分けた。val・test は race-known と同じ。
- 1段目：`probes/train_stage1.py`。ImageNet 初期化の ResNet-50。val AUROC が最大の epoch を使った。
- 植え込み：
  - マーカー（`planting.py`）は、A と val では陽性の 50%・陰性の 5% に付け、B と test ではラベルと独立に 20% に付けた。
    val のマーカーはラベルと相関しているため、補正の epoch 選択には B の患者 20% を取り分けて使った。
  - ペースメーカーは、レポート全文が pacemaker・pacer・AICD・defibrillator に触れる画像（全体の 8%）とした。A ではその陽性の 90% を捨てた。
- e(x)：`probes/embed.py`。RAD-DINO（518px）、DINOv2-base（224px）。CLS token と patch 平均を連結した 1536 次元。
- 補正：`latent_codes.py`。補正後 logit = 1段目の logit + ΔW_k·h(x) + Δb_k。ΔW_k = U·v(c_k) は低ランク。
  - 振り分けは Gumbel-softmax の straight-through で行う。
  - 損失は class weight 付き BCE ＋ λ Σ √p̄_k ‖(ΔW_k, Δb_k)‖ − β H(p̄)。
  - λ は 1e-4〜1e-2 で結果がほとんど変わらなかったので、1e-3 を既定にした。
- backbone 側：`probes/train_adapter.py`（hypernet_e2e の SpatialLoRAResNet を流用）。
- 文脈ラベル：`context_labels.py`。レポート種別は `fairness_mechanism_probe` と同じ正規表現。
- 評価：`stats.py` の患者単位 paired bootstrap（200回）。

## 限界

- 1段目はどの条件も seed 42 の1本で、run 契約の外の probe として回した。結論に使うなら hypernet_e2e の run として回し直す。
- 植え込みは2種類だけで、どちらも効果が大きい。実データにありそうな弱いバイアスでの検出力は確かめていない。
- マーカーはモデル側のショートカットの典型として作ったが、h(x) にこれほどはっきり出るのは植え込みの性質による。
- 文脈ラベルは正規表現による分類で、臨床的な正誤ではない。
- 振り分け係は Gumbel-softmax の1方式だけを試した。安定化（コードの事前初期化、複数 seed の合議）は未検証である。
