# ws とのデータ転送

研究室の 1 Gbps は共有回線である。過去に、帯域制限のない転送・無駄に多いセッション・
放置された並列転送で回線を重くしている。この文書はその再発を止めるための規約であり、
remote 作業のすべての転送に適用する。

## 役割分担（最上位の規則）

**エージェントは回線をまたぐ転送を実行しない。コマンドを組み立てて提示するだけにする。**

- `rsync` と `scp` を Bash で実行しない。train skill の `allowed-tools` にも含めていない
- 転送はユーザーが直接打つ。Claude Code なら prompt に `! <command>` と入力すれば、
  出力がそのまま会話に残るので、その後の確認をエージェントが引き継げる
- エージェントが実行してよいのは、転送の**判断材料を集める読み取り**だけ
  （`du -sh`、`ls`、ssh 経由の `du` / `ls` / `ps`）
- 承認済みの学習起動（ssh + detached docker）は転送ではないので、この制限の対象外とする

## 提示するコマンドが満たすこと

以下を満たさないコマンドを提示しない。ひとつでも欠けたら、それは提示してよい状態ではない。

1. **dry-run を先に出す。** `--dry-run --stats` 版と本番版を必ず 2 段で提示し、
   dry-run の `Total transferred file size` をユーザーに確認してもらってから本番を出す
2. **`--bwlimit=12500` を必ず付ける**（KiB/s、約 105 Mbps、共有 1 Gbps の約 10%）。
   `scp` は使わない。`scp -l` は Kbit/s なので同じ数値が約 8 倍違う意味になり、事故の元になる
3. **ControlMaster を再利用する。** `-e "ssh -o ConnectTimeout=10 -o ControlPath=~/.ssh/sockets/%r@%h-%p"`
   を必ず付ける。転送のたびに新しい SSH を張らない
4. **同時に走る転送は 1 本。** 複数の転送コマンドを並べて提示しない。1 本出して、完了を
   確認してから次を出す。`&` を付けたバックグラウンド転送を提示しない
5. **両側を glob しない。** src と dst はフルパスで書く
6. **exclude は [remote.md](remote.md) の一覧をそのまま使う。** 特に `/data` を外さない
7. **`-v` を付けない。** `--stats` だけにする。追跡ツリー全体の verbose 出力は数千行になる
8. **`--timeout=60 --partial` を付ける。** 切断時に最初からやり直さないため

## 規模による扱い

| 規模 | 例 | 扱い |
| --- | --- | --- |
| < 100 MB | コード同期、run metadata の回収 | 目的と概算を 1 行添えて提示する |
| 100 MB 〜 1 GB | checkpoint 数個 | サイズ・所要時間・なぜ今必要かを明示してから提示する |
| > 1 GB | `data/chexpert`（5.3 GB）、checkpoint 群 | **1 本の転送としては提示しない。** 分割単位（metadata 先行、checkpoint は 1 run ずつ）に割ってから提示する |

所要時間の目安（12500 KiB/s）: 100 MB ≈ 8 秒、1 GB ≈ 1.4 分、5.3 GB ≈ 7.2 分。
この間ほかの人の転送も遅くなる。所要時間は必ず提示に含める。

データセット本体の移送は学習の付随作業ではない。必要になったら、転送手段そのものを
（夜間実行、別経路、remote 側での再生成を含めて）ユーザーと決める。

## 提示前にエージェントが確認すること

```bash
du -sh <送る対象>
ps -eo args | grep -E '(rsync|scp)' | grep -v grep || true
ssh -o ConnectTimeout=10 -o ControlPath=~/.ssh/sockets/%r@%h-%p kohkiakiba@192.168.1.<N+10> \
  "ps -eo args | grep -E '(rsync|scp)' | grep -v grep || true"
```

すでに転送が走っていればコマンドを提示しない。終わるまで待つ。

## 提示の形

```text
目的: <何のために>
方向: local -> ws7 / ws7 -> local
対象: <path>
概算: <MB> / 約 <秒>（--bwlimit=12500）
他に走っている転送: なし（両側で確認済み）

1. dry-run:
<コマンド>

2. 問題なければ本番:
<コマンド>
```

## 実行後

ユーザーが貼った出力から、エージェントが次を確認して報告する。

- `Total transferred file size` が dry-run の見積もりと一致しているか
- exit code。特に 23（metadata の権限・timestamp）は、本体が届いていれば失敗と即断しない
- 回収した run directory の `run.json` / `preflight.json` が読めるか

再試行が要る場合も、再試行コマンドを提示するだけにする。副作用のある転送を、remote の状態を
確認しないまま再提示しない。

## 禁止

- エージェントによる `rsync` / `scp` の実行
- `--bwlimit` の無い転送コマンドの提示
- 並列転送、バックグラウンドへ逃がした転送の提示
- `scp -l` の値を `--bwlimit` に写すこと（単位が違う）
- GB 級の生データ転送を、学習手順の既定ステップとして組み込むこと
